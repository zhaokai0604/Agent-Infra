# Agent Infra 参赛方案：ThreshCore 零人工运维协同底座

## 1. 场景、问题与价值

企业生产环境的告警、日志、主机状态和处置经验通常散落在监控平台、脚本、工单和个人记忆中。告警出现后，运维人员需要跨系统收集证据、判断风险、执行脚本、验证恢复，再补写复盘；这既慢，也容易因权限过大、上下文丢失或“未验证即宣称完成”产生风险。

ThreshCore 将这一过程抽象为可审计的多 Agent 运维闭环：多源输入进入编排层，诊断角色组织证据，处置角色提出受控计划，验证审计角色确认实际效果并沉淀经验。目标不是消除人工，而是将人工从重复检索和脚本拼接中释放出来，把审批留在高风险、不可逆和关键资产操作上。

## 2. 多 Agent 闭环与 AgentTeams 映射

| 闭环环节 | AgentTeams 设计映射 | 当前工程底座 | 共享上下文 |
|---|---|---|---|
| 接收与拆解 | 主控/编排角色创建任务、分配子任务、维护状态 | `AssistantOrchestrator`、`OpsIntentRouter` | 任务目标、资产范围、`traceId`、风险级别 |
| 感知与诊断 | 诊断角色并行收集日志、巡检、RAG 证据 | 日志分析、巡检、知识库服务 | 健康快照、日志摘要、证据链接、置信说明 |
| 计划与处置 | 处置角色选择 Skill、生成最小化工具计划 | `AgentSkillPlan`、工具目录与分发器 | 计划步骤、参数摘要、Dry Run、效果指纹 |
| 验证与审计 | 验证角色检查结果；审计角色保存可追溯记录 | 效果门、审计 Trace、工作流/失败记忆 | 工具回执、前后指标、审批记录、验证结论 |

当前没有 AgentTeams SDK 依赖；上述表格是必须落地的集成契约。复赛适配层将把每个角色声明为 AgentTeams Agent，把 `AgentExecutionState` 和 `traceId` 映射为共享状态，把 Skill 调用与工具回执映射为可观察的任务事件。

## 3. Agent Identity 与职责边界

### A. 编排 Agent

- 身份：任务经理；负责将企业事件拆成可验证子任务。
- 输入：自然语言、告警、工单、日志索引与历史工作流。
- 输出：任务计划、角色委派、共享状态、下一步建议。
- 边界：没有直接写入权限；只能调度只读诊断或提交待审批处置计划。

### B. 诊断 Agent

- 身份：证据分析师；负责事实采集与根因假设。
- 输入：主机指标、日志、端口/服务状态、知识库检索结果。
- 输出：证据包、异常关联、根因假设、置信说明与补采集请求。
- 边界：只读工具优先；证据不足时必须返回“不足以处置”。

### C. 处置 Agent

- 身份：变更执行规划师；将诊断结论转为最小风险计划。
- 输入：诊断证据、资产等级、路径策略、工具目录、审批状态。
- 输出：Dry Run 计划、工具参数、预期效果、回滚线索。
- 边界：不能绕过 `McpInvocationSecurityGate`；真实写操作必须经过确认令牌和二次校验。

### D. 验证审计 Agent

- 身份：结果验证与合规记录员。
- 输入：执行回执、效果指纹、前后指标、风险决定和操作者信息。
- 输出：验证结论、Trace、审计事件、成功工作流或失败反思。
- 边界：没有验证证据不得标记完成；失败经验不能作为自动处置模板。

## 4. 核心 Skill 规范

### `ops-observe`

| 字段 | 契约 |
|---|---|
| 用途 | 聚合主机、网络、磁盘、端口与服务的只读健康证据。 |
| 输入 | `assetScope`、`metricHints`、`timeRange`。 |
| 输出 | 健康快照、异常线索、采集时间、`traceId`。 |
| 调用条件 | 告警首次进入、人工询问健康状态、诊断 Agent 请求补证据。 |
| 依赖 | `SystemLoadTool`、`DiskTool`、`PortHealthTool`、`ProcessTool`。 |
| 失败处理 | 返回部分证据和缺失项，不伪造健康结论；转为补采集或人工处理。 |
| 安全与复用 | 只读、资产范围受策略约束；可复用于容量、可用性与性能场景。 |

### `ops-diagnose`

| 字段 | 契约 |
|---|---|
| 用途 | 将日志、指标和历史知识组织为可审计的根因判断。 |
| 输入 | 健康快照、日志引用、知识库查询、历史 Trace。 |
| 输出 | 根因假设、证据摘要、置信度、候选处置建议。 |
| 调用条件 | `ops-observe` 发现异常或用户提交日志。 |
| 依赖 | 日志分析、`DiskAnalyzeTool`、RAG、工作流检索。 |
| 失败处理 | 置信度不足时输出补采集计划；不直接发起写操作。 |
| 安全与复用 | 数据脱敏后进入审计；可用于告警聚合、故障定位和复盘。 |

### `ops-remediate`

| 字段 | 契约 |
|---|---|
| 用途 | 生成并受控执行最小化处置计划。 |
| 输入 | 已确认的诊断、资产策略、审批状态、工具参数。 |
| 输出 | 预览结果、确认请求或实际执行回执、效果指纹。 |
| 调用条件 | 诊断证据达到处置阈值且风险策略允许。 |
| 依赖 | 工具目录、工具分发器、治理服务、确认服务。 |
| 失败处理 | 阻断、回退到 Dry Run 或转人工；记录失败原因与 Trace。 |
| 安全与复用 | 白名单、参数/路径校验、风险评分、会话预算、确认令牌、审计。 |

### `ops-verify-audit`

| 字段 | 契约 |
|---|---|
| 用途 | 验证处置效果并沉淀可复用证据。 |
| 输入 | 前后指标、工具回执、效果指纹、审批与风险结论。 |
| 输出 | 恢复/未恢复结论、审计 Trace、成功工作流或失败反思。 |
| 调用条件 | 每次处置、拒绝、超时或异常回执后。 |
| 依赖 | `McpAuditService`、效果校验、AWM、Reflexion。 |
| 失败处理 | 标记未闭环、附加复查任务；禁止把未验证结果写入成功记忆。 |
| 安全与复用 | 形成不可省略的证据链，可用于合规审计和后续策略评估。 |

## 5. 工具/MCP 集成与迁移

当前实现提供受控的内部工具目录及 HTTP 执行契约：工具名、参数、风险、只读属性、执行结果、`traceId` 和错误信息均可被稳定消费。它不是已经对外发布的标准 MCP Server；复赛适配时将保留现有 Schema 并增加 MCP Server 适配层：

1. 将工具目录映射为 MCP `tools/list`，将参数和返回信封映射为 JSON Schema。
2. 将调用统一映射为 `tools/call`，保持幂等键、超时、错误码、审计 Trace 和风险结果。
3. 认证采用服务身份 + 最小权限策略；写操作仍通过业务审批协议，而不是由模型绕过。
4. 工具返回 `success`、`status`、`traceId`、风险结论、效果指纹和脱敏证据摘要，以支持 AgentTeams 与观测平台消费。

这使现有工具层可迁移，而无需重新设计执行和安全链路。

## 6. 上下文、记忆与可观测

本方案已覆盖赛题建议的四类上下文能力中的至少两类：

- **共享状态管理：** `AgentExecutionState` 统一表达 objective → plan → act → verify → reflect，附带计划、审批、风险、工具与 `traceId`。
- **Agent 记忆：** AWM 只沉淀验证成功的工具序列和工作流；失败记录进入 Reflexion，而非污染成功模板。
- **知识库 RAG：** 文档切分与向量检索为诊断提供历史案例和 Runbook 证据；Qdrant 不可用时可降级。
- **轨迹可观测：** 审计 Trace 保留调用链与结果；工程包含 Prometheus 和 OpenTelemetry/OTLP 依赖，后续可接入 AgentScope Studio、LoongSuite 或 AgentLoop。

## 7. 安全、审批与回滚

- 只读工具优先，写工具在对话诊断阶段不挂载。
- 中风险动作返回确认请求；高风险、不可逆或资产策略禁止的动作直接阻断。
- 确认阶段复核操作者、参数、效果指纹和风险预算，避免确认快照被替换。
- 处置计划先经效果门检查组合写操作、不可逆性、核心服务重启等风险。
- 执行后必须保存审计与验证结论；部署文档提供版本回退与急停说明。
