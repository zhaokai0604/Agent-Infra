# ThreshCore（award-log）部署文档

**部署方式**：Fat Jar 后端 + Nginx 反向代理前端与 API（推荐生产）

| 项 | 说明 |
|----|------|
| **系统名称** | ThreshCore 控制台 + award-log 后端 |
| **Context Path** | `/award-log` |
| **业务端口** | `8088`（`server.port`，Jar 主监听） |
| **管理端口** | `8089`（仅 **dev 联调** 默认开启；`prod-kylin` 默认关闭） |
| **对外端口** | Nginx `80` / `443`（生产用户访问） |
| **默认数据库** | **MariaDB 10.6+**（`jdbc:mariadb://…`）；MySQL 8 可切换 |
| **技术栈** | Java 17 · Spring Boot 3.5 · Vue 3 · Vite · Nginx |
| **文档版本** | 2026-06-20 |

## 1. 部署架构

### 1.1 生产（prod-kylin，推荐）

```
用户浏览器
    │
    ▼
Nginx :80 / :443              ← 唯一对外入口
    ├── /                     → /opt/threshcore/dist/（Vue 静态）
    └── /award-log/           → 反代 http://127.0.0.1:8088/award-log/
                                    │
                                    ▼
                             award-log.jar（systemd，User=root）
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
              MariaDB 10.6+    DashScope API    Qdrant（可选，RAG）
              （必选）         （AI 对话需要）   docker compose
```

**要点**：

- Jar **只监听 8088**；`app.management.enabled=false`（默认），所有 REST/SSE/WebSocket 经同一端口。
- MCP 工具在宿主机执行 OS 命令（经 `MinPrivilegeExecutor` 降权为 `award-agent`），**不要把应用本身放进 Docker**。
- Kafka / Redis / Elasticsearch 默认关闭（`AWARD_MIDDLEWARE_*=false`），无需部署。

### 1.2 开发（dev profile，双端口）

| 端口 | 角色 | 典型路径 |
|------|------|----------|
| **8088** | 业务面 | `/log/**`、`/api/v1/knowledge/**`、`doc.html`（Knife4j） |
| **8089** | 管理面 | `/admin/**`、`/api/assistant/**`、`/api/mcp/**`、`/api/ops/**` |

`ManagementPortFilter` 强制路径与端口匹配。前端 `npm run dev`（`:3000`）通过 `vite.config.js` 将管理类 API 代理到 **8089**。

启动成功标志（日志中应同时出现）：

```text
Starting ProtocolHandler ["http-nio-8088"]
Starting ProtocolHandler ["http-nio-8089"]
```

| 场景 | Profile | 构建命令 | 产物目录 | 对外访问 |

| 本地开发 | `dev` | `mvn spring-boot:run` + `npm run dev` | — | `http://localhost:3000` |

## 4. 开发环境联调（Windows / Linux）

### 4.1 启动数据库（Docker，推荐 MariaDB）

```bash
cp .env.example .env
# 编辑 .env 设置 MARIADB_ROOT_PASSWORD

docker compose up -d mariadb
# 可选 RAG：docker compose up -d qdrant

docker compose exec -T mariadb mariadb -uroot -p"${MARIADB_ROOT_PASSWORD}" log_analysis \
  < src/main/resources/schema.sql
```

> Windows 本地也可用 MySQL 8：见 `application-local.example.yml` 覆盖 `jdbc:mysql://…`。

### 4.2 配置本地密钥

```bash
copy src\main\resources\application-local.example.yml src\main\resources\application-local.yml
# 填写 DB_PASSWORD、AI_API_KEY（OpenAI 兼容，如 DashScope / DeepSeek）
```

### 4.3 启动后端

```bash
mvn spring-boot:run
# 默认 profile=dev；确认 8088 与 8089 均已监听
```

`application-dev.yml` 已固定：

- `app.management.enabled: true`
- `app.management.port: 8089`
- `agent.min-privilege.enabled: false`（Windows 无 sudo 时可跑通）

### 4.4 启动前端

```bash
cd frontend
npm install
npm run dev
# 浏览器 http://localhost:3000
```

`frontend/.env.development` 默认 `VITE_DEV_PROXY_TARGET=http://127.0.0.1:8088`；管理 API 自动走 **8089**（见 `vite.config.js` 与 `src/api/index.js`）。

### 4.5 开发联调验收

```bash
# 端口
ss -lntp | grep -E '8088|8089'          # Linux
netstat -ano | findstr ":8088 :8089"     # Windows

# 健康
curl -s http://127.0.0.1:8088/award-log/actuator/health
curl -s http://127.0.0.1:8089/award-log/api/mcp/tools | head -c 200
```

### 4.6 提交前质量门禁

```bash
mvn verify
# 报告：target/site/jacoco/index.html（指令覆盖率门禁 ≥60%）
```

## 5. 构建产物

### 5.1 前端构建环境变量（生产必看）

Nginx **同域**部署时，构建前创建 `frontend/.env.production`：

```bash
# 将 your.domain 换为实际域名或 IP（无末尾斜杠）
VITE_AWARD_LOG_BASE_URL=http://your.domain/award-log
# prod-kylin 管理面默认关闭，管理 API 与业务 API 同域同端口，两行应一致：
VITE_AWARD_LOG_MANAGEMENT_BASE_URL=http://your.domain/award-log
```

未设置时，前端可能错误请求 `:8089`，导致登录或 MCP 失败。

### 5.2 通用构建

```bash
PROD_BUILD=1 bash scripts/deploy/deploy.sh
# 产物：deploy/release/
#   award-log.jar
#   dist/
#   nginx.sample.conf
#   README-DEPLOY.txt
```

Windows：`$env:PROD_BUILD='1'; .\scripts\deploy\deploy.ps1`

### 5.3 麒麟龙芯构建（须在目标架构执行）

```bash
bash scripts/deploy/deploy_kylin_loongarch.sh
# 产物：deploy/release-kylin/
#   award-log.jar, dist/
#   env.kylin.prod.example
#   award-log.service
#   nginx.kylin.sample.conf
#   smoke_kylin_acceptance.sh
#   setup_kylin_host.sh
#   sudoers.award-agent.example
```

脚本强制 `mvn verify`（`SKIP_TESTS=0`）。

## 6. 麒麟 V11 + LoongArch 生产部署

### 6.1 首次主机准备（root）

```bash
cd /path/to/threshcore
sudo bash scripts/deploy/setup_kylin_host.sh
```

自动完成：MariaDB 启停 + 建库导入 `schema.sql`、创建 `award-agent`、安装 `/etc/sudoers.d/award-agent`、生成 `/etc/threshcore/threshcore.env` 模板、创建 `/opt/threshcore/logs`。

### 6.2 构建（龙芯本机）

```bash
bash scripts/deploy/deploy_kylin_loongarch.sh
```

### 6.3 安装应用

```bash
sudo mkdir -p /opt/threshcore/logs
sudo cp deploy/release-kylin/award-log.jar /opt/threshcore/
sudo cp -r deploy/release-kylin/dist /opt/threshcore/
sudo cp deploy/release-kylin/award-log.service /etc/systemd/system/

sudo cp deploy/release-kylin/env.kylin.prod.example /etc/threshcore/threshcore.env
sudo chmod 600 /etc/threshcore/threshcore.env
# 编辑：DB_PASSWORD、AI_API_KEY 等
sudo systemctl daemon-reload
sudo systemctl enable --now award-log
```

### 6.4 环境变量（threshcore.env 最小集）

见 [`scripts/deploy/env.kylin.prod.example`](../../scripts/deploy/env.kylin.prod.example)，关键项：

```bash
SPRING_PROFILES_ACTIVE=prod-kylin

DB_URL=jdbc:mariadb://127.0.0.1:3306/log_analysis?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
DB_USERNAME=threshcore
DB_PASSWORD=<强密码>

AI_API_KEY=<DashScope 或 DeepSeek 兼容密钥>
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode

# 浏览器/Nginx 正式入口的 Origin 白名单；多个来源用英文逗号分隔
APP_CORS_ALLOWED_ORIGIN_PATTERNS=https://threshcore.example.com

AGENT_RUN_AS_USER=award-agent
# 生产使用专用低权限账号；写操作仍受路径白名单、治理与确认门控约束
AGENT_MIN_PRIVILEGE=true

APP_AI_AUDIT_RELAXED_READ=false
OPS_DRY_RUN_GLOBAL=false
OPS_AUTO_REMEDIATION_ENABLED=true
OPS_AUTO_REMEDIATION_MODE=HYBRID
OPS_PATROL_ENABLED=true
RF_FORCE_HEURISTIC_LOONGARCH=true

AWARD_MIDDLEWARE_KAFKA=false
AWARD_MIDDLEWARE_REDIS=false
ELASTIC_ENABLED=false
```

> `application-kylin.yml` 已内置路径白名单（`/var/log`、`/tmp` 等）与 `agent.paths.policy-version=path-policy-v2-kylin-loongarch`。

> **访问来源白名单必须按现场修改**：将 `APP_CORS_ALLOWED_ORIGIN_PATTERNS` 设置为实际控制台的 `http(s)://域名[:端口]`。该配置同时用于浏览器 CORS、登录态写请求的来源校验和 WebSocket 握手；多个来源用英文逗号分隔。生产不要配置 `*`，也不要把 `localhost` 当作正式域名白名单。

### 6.5 Nginx（推荐）

```bash
sudo cp deploy/release-kylin/nginx.kylin.sample.conf /etc/nginx/conf.d/threshcore.conf
# 修改 server_name、root=/opt/threshcore/dist
sudo nginx -t && sudo systemctl reload nginx
```

### 6.6 自动化验收

```bash
export BASE=http://127.0.0.1:8088/award-log
bash deploy/release-kylin/smoke_kylin_acceptance.sh
```

| 检查项 | 通过标准 |
|--------|----------|
| Health | `/actuator/health` → UP |
| 交付目标 | `/api/platform/acceptance` 中 `deliveryTargetMatch: true` |
| MCP | `/api/mcp/tools` 含 `AutonomousOpsTool` |
| 巡检 | `POST /api/ops/autonomous/run?readOnly=true` 返回 traceId |

完整清单：[`麒麟V11-LoongArch生产上线检查清单.md`](./麒麟V11-LoongArch生产上线检查清单.md)

## 8. Nginx 反向代理

### 8.1 最小配置

```nginx
server {
    listen 80;
    server_name _;

    root /opt/threshcore/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /award-log/ {
        proxy_pass http://127.0.0.1:8088/award-log/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    # 生产建议禁止公网访问
    location /award-log/doc.html { deny all; return 403; }
    location /award-log/actuator/ { deny all; return 403; }
}
```

### 8.2 访问地址

| 用途 | URL |
|------|-----|
| 控制台（经 Nginx） | `http://<域名>/` |
| 平台验收（免登录） | `http://<域名>/award-log/api/platform/acceptance` |
| 本机排查（勿对用户开放） | `http://127.0.0.1:8088/award-log/...` |

| 变量 | 必填 | prod-kylin 建议 | 说明 |

## 10. 数据库初始化

```sql
CREATE DATABASE IF NOT EXISTS log_analysis
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'threshcore'@'localhost' IDENTIFIED BY 'your_password';
GRANT ALL PRIVILEGES ON log_analysis.* TO 'threshcore'@'localhost';
FLUSH PRIVILEGES;
```

```bash
mariadb -u threshcore -p log_analysis < src/main/resources/schema.sql
mariadb -u threshcore -p -e "USE log_analysis; SHOW TABLES;"
```

应含 `ops_audit_trace`、`sys_user`、`log_analysis_task` 等。AWM seed 在 Jar 首次启动时写入。

## 11. systemd 托管

服务单元 [`scripts/deploy/award-log.service`](../../scripts/deploy/award-log.service)：

- **User=root**（Jar 进程身份；OS 命令经 `MinPrivilegeExecutor` 降权）
- **WorkingDirectory=/opt/threshcore**
- **EnvironmentFile=/etc/threshcore/threshcore.env**
- **ExecStart**：`java -Xms256m -Xmx1024m -XX:MaxMetaspaceSize=256m -jar /opt/threshcore/award-log.jar`

```bash
sudo systemctl status award-log
sudo journalctl -u award-log -n 80 --no-pager
sudo systemctl restart award-log
```

## 14. 升级、回滚与急停

### 升级

```bash
sudo systemctl stop award-log
sudo cp /opt/threshcore/award-log.jar /opt/threshcore/award-log.jar.bak
# 龙芯本机重新构建后：
sudo cp deploy/release-kylin/award-log.jar /opt/threshcore/
sudo cp -r deploy/release-kylin/dist /opt/threshcore/
sudo systemctl start award-log
```

### 回滚

```bash
sudo systemctl stop award-log
sudo cp /opt/threshcore/award-log.jar.bak /opt/threshcore/award-log.jar
sudo systemctl start award-log
```

### 急停写操作

在 `threshcore.env` 设置：

```bash
OPS_AUTO_REMEDIATION_ENABLED=false
OPS_DRY_RUN_GLOBAL=true
```

然后 `sudo systemctl restart award-log`。

## 16. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 前端 3000 无法登录 | 仅 8088，8089 未启 | 确认 dev profile；日志含双端口 |
| 页面开、API 全挂 | 生产未设 `VITE_AWARD_LOG_*` | 重建前端，两 Base URL 均指向 Nginx 同域 |
| Nginx 404 | proxy_pass 缺 `/award-log/` | 末尾必须为 `http://127.0.0.1:8088/award-log/` |
| Jar 启动即退出 | `DB_PASSWORD` 空 | 检查 threshcore.env |
| `deliveryTargetMatch=false` | 非麒麟龙芯或 Profile 错 | `SPRING_PROFILES_ACTIVE=prod-kylin` |
| Jar 在龙芯无法运行 | x86 编译产物 | 龙芯本机 `deploy_kylin_loongarch.sh` |
| MCP Permission denied | sudoers 未装 | `setup_kylin_host.sh` 或手动装 sudoers |
| AI 无回复 | 密钥无效 / 网络 | 更新 `AI_API_KEY`、`AI_BASE_URL` |
| WebSocket 断 | Nginx 无 Upgrade | 使用 `nginx.kylin.sample.conf` |
