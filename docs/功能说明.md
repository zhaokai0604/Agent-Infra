# ThreshCore 功能说明

本文用于快速定位每个功能的入口、实现位置和维护注意事项。新增功能或修改现有功能时，应同步更新本表。

## 功能总表

| 功能 | 前端入口 | 后端入口 | 维护备注 |
|---|---|---|---|
| 登录与用户 | `Login.vue`、`UserProfileCenter.vue` | `AuthController`、`UserController` | 修改权限时同时检查 Spring Security、RBAC 和数据 owner 过滤。 |
| Agent 工作台 | `components/agent/`、`OpsChatInterface.vue` | `AssistantOrchestrator`、`OpsRuntimeService` | 负责意图识别、上下文整理、工具规划和自然语言结果输出。 |
| 意图路由 | Agent 工作台快捷入口 | `OpsIntentRouter`、`LlmPlaybookClassifier` | 规则优先；模型分类只做补充，失败时必须回落到安全默认分支。 |
| 日志上传与分析 | `LogAnalysis.vue`、`LogAnalysisDashboard.vue` | `LogAnalysisController`、`LogAnalysisService` | 上传、解析、模板提取、异常诊断和报告导出是一条完整链路。 |
| MCP 工具目录 | `ToolConsole.vue`、`AgentSkillsPage.vue` | `McpToolCatalog`、`McpToolRegistry` | 新工具必须注册、补参数说明、定义权限边界并增加测试。 |
| MCP 工具执行 | `mcpToolExecute.js`、`ToolResultDialog.vue` | `McpToolDispatcher`、`McpExecuteController` | 统一处理参数、超时、结果状态、确认和审计。 |
| 安全门控 | `SecurityCockpit.vue`、`SecuritySelfCheckDialog.vue` | `McpInvocationSecurityGate`、`OpsGovernanceService` | 任何写操作都不能绕过风险判断、路径策略和确认流程。 |
| 磁盘与临时文件 | Agent / MCP 工具控制台 | `DiskTool`、`DiskOpsTool`、`CleanTempTool` | 默认只读；清理类操作必须支持预览、范围限制和结果验证。 |
| 日志清理与服务操作 | Agent / MCP 工具控制台 | `LogCleanupTool`、`ServiceRestartTool` | 服务重启和日志清理必须有白名单、风险分级和审计记录。 |
| 自动巡检 | `OpsLiveWall.vue`、巡检页面 | `OpsPatrolService`、`OpsPatrolController` | 采集磁盘、CPU、内存、进程、服务和网络状态并形成告警。 |
| 自动处置 | `RemediationPlanCard.vue`、`OpsEffectDashboard.vue` | `OpsAutoRemediationService` | 巡检结果先生成方案，再按风险进入自动、确认或人工处理。 |
| 运维审计 | `AuditCenter.vue`、`OpsTraceCenter.vue` | `AuditController`、`OpsTraceController` | 记录用户、Agent、Skill、工具、参数摘要、决策和验证结果。 |
| AWM 工作流记忆 | `OpsMemoryPanel.vue` | `WorkflowMemoryService`、`WorkflowInductionService` | 只保留成功并完成验证的工作流，避免把失败方案当作模板复用。 |
| Reflexion 安全教训 | 安全教训页面 | `FailureInsightService` | 记录拦截、失败、缺失证据和改进建议，供后续诊断参考。 |
| 知识库 RAG | `KnowledgeBase.vue` | `KnowledgeController`、`KnowledgeBaseService` | Qdrant 不可用时应按配置降级，不影响基础日志和工具功能。 |
| 安全信号 | 安全态势页面 | `SecuritySignalService`、`SecuritySignalNormalizer` | 负责接入、归一化、摘要和与巡检上下文关联，不等同于独立 IDS。 |
| 平台状态 | `EnvironmentStatus.vue` | `PlatformInfoController`、`PlatformReadinessController` | 用于检查数据库、AI、MCP、可选中间件和后端探针。 |
| 配置中心 | `SystemConfigCenter.vue` | 配置 Properties、配置 Controller | 修改默认值时同步更新示例配置和 README。 |
| 报表导出 | 看板、审计和链路页面 | `dashboardExport.js`、`tableExport.js` | 导出内容应使用脱敏数据，避免把密钥和内部路径带入文件。 |

## 统一修改原则

1. Controller 只负责协议和权限，不把复杂业务逻辑堆在接口方法中。
2. Agent 负责理解和编排，Skill 负责可复用能力，MCP 工具负责受控执行。
3. 新增写操作时，必须补充 ALLOW / CONFIRM / BLOCK 规则和失败路径。
4. 任何执行类功能都应保留 traceId、结果状态和可读错误信息。
5. 配置必须通过环境变量或本地配置覆盖，不能把真实密钥写进源码。
6. 修改 `schema.sql` 或 Mapper 后，同时更新测试数据库结构并运行相关测试。
7. 修改前端路由、端口或 API 基址后，同时检查 Vite 代理和生产配置。

## 主要入口速查

```text
后端启动：mvn spring-boot:run
前端启动：cd frontend && npm run dev
后端测试：mvn verify
前端构建：cd frontend && npm run build
默认后端：http://localhost:8088/award-log/
默认前端：http://localhost:3000
```
